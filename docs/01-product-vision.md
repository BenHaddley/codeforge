# 01 — Product Vision

## Identity

Display name: **Code Forge**  
Repository/product slug: `codeforge`  
Visual identity: **late-1990s / early-2000s desktop training software** rather than a modern SaaS dashboard.

The nostalgia should be a functional design system, not just decoration. The site should feel like someone installed a boxed programming course from a CD-ROM, except the exercises actually execute real code in the browser.

## Product promise

Code Forge should eliminate the gap between "I just read/watched this" and "I can actually use it." Every learning unit ends with the learner doing something observable in code.

## Primary user

A self-directed beginner or early-intermediate developer who likes books/videos but needs structure, immediate practice and visible progress.

## Differentiators

1. **One-screen learning workspace.** Explanation, examples, video, assignment, IDE, output and tests stay together.
2. **Book companion tracks without replacing the book.** The site can map to chapter concepts while keeping its own writing and exercises.
3. **Curated external teaching clips.** Video is reinforcement, not the entire course.
4. **Desktop-app aesthetic.** Windows-98-style hierarchy, dense controls, title bars, tree views, tabs and status bars.
5. **Real execution from the first useful lesson.** Python can run client-side with Pyodide in the early version.
6. **Progress that represents demonstrated skill.** XP comes from checks, assignments and projects rather than page views.

## What Code Forge is not

- Not a mirror of Boot.dev.
- Not a copy of Python Crash Course.
- Not a playlist wrapper.
- Not a passive video course.
- Not an AI answer generator.
- Not a fake IDE where the answer is checked by string matching.

## North-star metric

**Verified assignments completed per active learner per week.**

This is more meaningful than time-on-site because Code Forge is supposed to turn consuming information into writing working code.
