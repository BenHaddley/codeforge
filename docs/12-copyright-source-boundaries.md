# 12 — Copyright and Source Boundaries

Code Forge can be a companion to books and videos without becoming a copy of them.

## Books

Safe product structure:
- identify the book, author, edition and chapter;
- link to the publisher/book page;
- write an independent summary of the concept;
- create new examples;
- create new exercises/tests;
- encourage the learner to own/read the source where the track is explicitly a companion.

Do **not** place chapter prose, exercise text, diagrams or solution text from a copyrighted book into the repository unless you have permission/license to do so.

## TTS

TTS should narrate Code Forge's own text. Converting copied book pages to speech does not solve the underlying rights issue.

## YouTube

Use the creator's embed/player and deep-link to timestamps. Do not download the chapter, crop it into a local MP4 and ship it with the site unless the creator grants the necessary permission.

For the current Bro Code example, keep only:
- YouTube video ID;
- start/end timestamps;
- creator/title attribution;
- external link/embed.

## User-supplied private notes

If Code Forge later allows users to paste their own notes for personal use, keep those private to the user and separate from published curriculum content.

## Product labeling

For companion tracks, make the relationship clear:

> Independent companion exercises for Python Crash Course. Code Forge is not affiliated with No Starch Press or Eric Matthes.

Do the same for external video creators.
